# 生产排期（PMC）方案 · 待确认

来源：2026-11-12 第三轮岗位复核（PMC 体验者模拟一周计划工作）+ 用户要求“要有个地方专门做生产排期，不一定按天”。
状态：**方案稿，待业务确认后实现**。

## 一、现状与缺口

- 系统里**没有排期层**：工单只有 `planned_start / planned_end`（= 交期 − 固定生产周期，与数量、负荷无关，会落在周日）；`RoutingOperation.std_minutes` 没参与任何计算；`WorkCenter` 没有产能字段；没有工作日历。
- 计划员在系统里做不了：按线 × 日期排工单、看哪天超载、插单后看谁被挤后、给班组长下发“今天做什么”、看计划达成。
- 插单抢料时没有提示，交付风险卡反而可能变乐观（缺料没有到货日期时算不出预计完工，见 A-R3-3）。

## 二、粒度：第一版按“工作中心 × 天”，模型预留班次/小时

| 粒度 | 适合 | 本厂用法 |
|---|---|---|
| 周 | 接单评审、粗能力平衡（与 MRP 一致） | 看板可切换的缩放视图 |
| **天** | 早会、日报、报工汇总一致；标准工时有误差也能用；一个计划员维护得动 | **第一版主粒度** |
| 班次 | 两班倒更准 | 第二版；第一版只用来算每天可用工时 |
| 小时级甘特 / APS | 工序衔接最精确，但依赖准确工时与换型 | 以后只对 SMT、老化等瓶颈做 |

理由：单张订单 10–200 台，一张工单在总装线上占 1–3 天；瓶颈是设备（老化架、光谱仪、安规仪、贴片机），演示数据的标准工时尚未认真维护。

## 三、第一版范围（建议）

1. **产能与日历**：工作中心加产能（人工型：人数 × 班次净时长 × 效率；设备型：可用设备台数；批次型如老化：架位数 × ⌊可用小时 ÷ 老化时长⌋）、换型分钟；全厂工作日历 + 按工作中心的例外（停线、加班、临时人数）。
2. **排期看板 `/plan/schedule`**：
   - 左侧待排池（交期 D-n、剩余数量、齐套灯、客供料状态、最早可开工日 = max(齐套日, 客供料承诺日, 半成品完工日 + 1)）；
   - 主区 行 = 工作中心、列 = 日期（14 天，可切周）；每格显示负荷条（如 36.5 / 40.8h，>100% 标红）和工单条（工单号、型号、当日数量 / 剩余、交期、齐套灯、锁定、换型标记）；
   - 顶部提示：超载格数、预计晚交工单数、排在齐套日之前的工单数、需重排工单数。
3. **排主工序**：每条工艺路线指定一道主工序（默认第一道；成品通常是总装，半成品是 SMT），后段工序按偏移天数跟排、只显示负荷用来暴露瓶颈。
4. **调整**：拖入格子按产能自动拆到连续工作日（跳过休息日）；改某天数量，剩余自动顺延；锁定；冻结期（默认今天和明天，改动须填原因）；**插单**时同线后面未锁定的工单顺延，保存前弹出影响清单（谁推后几天、谁会晚于交期、哪些物料被挤占）；撤销上一步。
5. **一键顺排（先预览差异再确认）**：已开工和锁定的不动，其余按 交期 → 优先级 → 下单先后，从最早可开工日起有限产能正排，同产品尽量相邻，排不进交期的标红“晚 N 天”。约束以提示为主、允许超排但留痕。
6. **发布与下发**：发布生成计划版本并回写工单计划开工/完工（之后再改留痕）；每日派工单按工作中心/班组打印（顺序、工单、批号、当日数量、齐套、首件/换型提示）；班组长工作台“本线今日派工”；工位顶部显示“本线今日：WOxxx 20 台，已完成 12”（扫到非今日计划的工单只提示不拦截）。
7. **计划 vs 实际**：实际取主工作中心最后一道工序当天的合格过站数；当日达成 < 80%、累计落后 > 1 天或落后导致晚交时进计划员待办（严重的进风险卡）；未完成量一键滚到下一工作日。
8. **联动**：订单变更/工单调整 → 工单标“需重排”；新工单直接进待排池；MRP 组件需求日期读排程回写的开工日；齐套分配按排程顺序；交付风险卡预计完工改为 排程末日 + 后段天数 + 放行天数；客供料通知增加客户承诺到料日 / 实到日期。

**以后再做**：班次级排程、SMT/老化小时级甘特、换型优化、人员资质约束、设备保养占用、全工序 APS、接单可承诺交期（CTP）、方案对比、车间大屏实时推送、工单合并与拆分（A-R3-11，可先单独做）。

## 四、数据与页面（第一版）

| 对象 | 新增 |
|---|---|
| `WorkCenter` | `is_schedulable`、`capacity_mode`（LABOR / MACHINE / BATCH）、`headcount`、`efficiency`、`batch_slots`、`batch_hours`、`changeover_minutes`、`shift_pattern_id` |
| 新表 `ShiftPattern` | 班次起止、休息分钟、净时长 |
| 新表 `WorkCalendar` | 日期、工作中心（空 = 全厂）、是否工作日、班次 / 工时 / 人数覆盖、原因 |
| `RoutingOperation` | `is_pacing`（主工序）、`setup_minutes`、`offset_days` |
| `WorkOrder` | `due_date`、`schedule_status`（未排 / 已排 / 需重排）、`parent_wo_id`（半成品 → 成品） |
| 新表 `ScheduleEntry`（核心） | 工单、工作中心、日期、预留班次、数量、分钟、顺序、锁定、状态、备注 |
| 新表 `SchedulePublish` | 版本号、日期范围、发布人 / 时间、快照 |
| 新表 `ScheduleLagReason` | 工单、日期、原因代码、数量、登记人 |
| `MrpSuggestion` | `customer_promised_date`、`customer_received_at`（客供料承诺 / 实到） |

页面：`/plan/schedule`（排期看板）、`/plan/dispatch`（每日派工单）、`/plan/calendar`（日历与产能）、`/plan/board`（车间看板，可放第二步）；工作中心页加产能字段；PMC 工作台加“今日计划达成 / 需重排”，班组长工作台加“本线今日派工”。

接口：`GET /api/schedule`（产能、排程明细、待排池）、`POST /api/schedule/entries`（新增 / 移动 / 拆分 / 锁定）、`POST /api/schedule/auto`（一键顺排，先预览）、`POST /api/schedule/publish`、`GET /api/schedule/dispatch`、`GET /api/schedule/plan-vs-actual`。

## 五、需要业务确认

1. 第一版按“工作中心 × 天”是否可以（班次、小时级以后再做）？
2. 主工序：成品默认总装线、半成品默认 SMT，是否符合实际？
3. 冻结期默认“今天 + 明天”是否合适？
4. 标准工时目前没认真维护：第一版允许按“物料生产周期折算日产量”兜底并提示“负荷仅供参考”，可以吗？
5. 第一版是否需要车间看板（大屏），还是先做打印派工单 + 工位顶部显示？
